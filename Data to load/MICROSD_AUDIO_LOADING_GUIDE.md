# Руководство по подготовке аудио для microSD

Это руководство описывает, как получить корректные звуковые файлы на microSD-карту для ESP32-прошивки Nixie Clock и как пользоваться скриптом конвертации.

> Сценарии ниже разделены на два основных случая:
> 1) вы уже имеете готовые WAV-файлы и просто загружаете их вручную;
> 2) у вас файлы в другом формате или их нужно получить из CD/кассеты/скачать из Интернета.

---

## 1. Что должна содержать карточка microSD

На корне карты памяти должны быть следующие папки:

```
SD:/
├── alarms/
├── system/
├── sfx/
└── ...
```

Каждая папка содержит WAV-файлы, которые устройство читает по категориям:

- alarms/ — будильники и тревоги
- system/ — системные звуки: старт, приветствие, уведомления
- sfx/ — короткие эффекты и служебные сигналы

Файлы внутри этих каталогов должны иметь имя в формате:

```
Пример для будильников:
alarm_1__Back_to_the_future__02-buckingham_lindsey_-_time_bomb_town.wav
Для системных файлов:
system_1__Wintergatan_-_Marble_Machine.wav
Для файлов уведомлений (звуков):
sfx_1__ble_connect.wav
```
Полная структура имени:

- prefix: короткий идентификатор устройства, например alarm_1
- suffix: человекочитаемый суффикс, содержащий источник/трек/название

ВАЖНО!
Как видим, prefix состоит из назначения [alarm/system/sfx] и индекса [1,2 и т.д.]. Пара назначение_индекс не может повторятьсяв рамках каждой папки. Назначение и номер в идексе разделяються нижним подчёркиванием "_".
Т.е. для устройства важен короткий детерминированный prefix с чётко фиксированными полями, а для человека — понятный и безопасный суффикс, чтобы понять “что именно это за звук”.

---

## 2. Нормы аудио для устройства

Для корректного воспроизведения устройство ожидает WAV-файлы со следующими параметрами:

- PCM, 16-bit
- sample rate:
  - alarm: 22050 Hz
  - system: 16000 Hz
  - sfx: 16000 Hz
- channels:
  - alarm: 1 (моно)
  - system: 1 (моно)
  - sfx: 1 (моно)
- codec: PCM S16LE

Рекомендуемая схема:

- Будильники: 22050 Hz, 1 channel, 16-bit PCM
- Системные звуки: 16000 Hz, 1 channel, 16-bit PCM
- Эффекты: 16000 Hz, 1 channel, 16-bit PCM

Если файлы сделаны в другом формате или на другом битрейте — их нужно привести к этим условиям. Слишком длинный путь, слишком высокий битрейт или неподходящая частота не поддерживаються.

## 3. Сценарий 1: прямой ручной перенос готовых WAV-файлов

Этот сценарий подходит, когда у пользователя уже есть готовые .wav-файлы.

### Шаги

1. На ПК подготовить необходимые директории:

```
Data to load/
├── Sounds for the microSD card/
│   ├── alarms/
│   ├── system/
│   ├── sfx/
│   └── _source_mp3/
```

2. Для каждой категории положить WAV-файлы в соответствующую папку:

- alarms/ — треки будильников
- system/ — системные сообщения и мелодии
- sfx/ — короткие сигналы

3. Присвоить им правильное имя и разложить в соответствующие папки.

Примеры.
```
- alarms/
alarm_1__Back_to_the_future__02-buckingham_lindsey_-_time_bomb_town.wav
alarm_2__Back_to_the_future__05-huey_lewis_and_the_news_-_back_in_time.wav
- system/
system_1__Wintergatan_-_Marble_Machine.wav
system_2__Wintergatan_-_Sommarfågel.wav
- sfx/
sfx_1__ble_connect.wav
```

4. Проверить, что файлы реально находятся в корне карты памяти не в любом другом каталоге:

```
SD:/alarms/
SD:/system/
SD:/sfx/
```

5. После этого вставить карточку в устройство и проверить воспроизведение.

### Важное замечание

Если вы вручную кладёте файлы в папки и хотите сохранить порядок и стабильную работу, лучше не менять имена уже принятых файлов. Иначе привязки alarm_1, alarm_2, system_1 и т. п. могут сломаться при логике обработки или при обновлении набора композиций.

## 4. Сценарий 2: у вас есть файлы в другом формате или их нужно скачать/оцифровать

Этот сценарий применяется, если источники находятся в .mp3, .flac, .aac, на кассете, DVD, CD, MP3-плеере, старой записи или просто скачаны из интернета.

### Шаги

1. Подготовить рабочую структуру на ПК:

```
Data to load/
├── Sounds for the microSD card/
│   ├── alarms/
│   ├── system/
│   ├── sfx/
│   └── _source_mp3/
│       ├── alarms/
│       ├── system/
│       └── sfx/
```

2. Скачивание / оцифровка / конвертация:

- Если есть готовые MP3 — их кладём в папки `_source_mp3/alarms`, `_source_mp3/system`, `_source_mp3/sfx`.
- Если источник записан на кассете/диске — сначала выполнить оцифровку в максимально возможном качестве.
- Если есть возможность, лучше сразу получать .wav, чтобы сразу использовать сценарий 1 и не тратить время на дополнительную конвертацию.
- Если вы используете MP3, старайтесь брать максимально честный и хороший битрейт на этапе скачивания или оцифровки, чтобы не терять качество при последующей конвертации.

3. Разложить исходники в `_source_mp3` по соответствующим папкам:

```
Data to load/Sounds for the microSD card/_source_mp3/alarms/
Data to load/Sounds for the microSD card/_source_mp3/system/
Data to load/Sounds for the microSD card/_source_mp3/sfx/
```

4. Открыть PowerShell или cmd в папке проекта и запустить скрипт:

```
cd "D:\Private\NIXIE Clock\SW ESP32 based"
python ".\Data to load\convert_mp3_to_wav.py" --profile alarm
```

5. Для других категорий запускаются другие профили:

```
python ".\Data to load\convert_mp3_to_wav.py" --profile system
python ".\Data to load\convert_mp3_to_wav.py" --profile sfx
python ".\Data to load\convert_mp3_to_wav.py" --profile music
```

6. Скрипт автоматически:

- ищет MP3 в `_source_mp3`
- определяет категорию по пути (`alarms`, `system`, `sfx`)
- читает профиль обработки
- конвертирует в WAV
- создаёт имена в формате device_id + human suffix
- сохраняет итоговые файлы в папки `alarms/`, `system/`, `sfx/`
- пишет отчёт в `audio_manifest.csv`

7. По завершении копировать содержимое каталогов `alarms`, `system`, `sfx` в корень карточки microSD.

## 5. Как пользоваться скриптом convert_mp3_to_wav.py

Файл находится здесь:

```
Data to load/convert_mp3_to_wav.py
```

### Что он делает

Скрипт конвертирует подготовленные MP3-файлы в WAV-файлы, подходящие для устройства, и раскладывает их по папкам:

- `_source_mp3/alarms` → `Sounds for the microSD card/alarms`
- `_source_mp3/system` → `Sounds for the microSD card/system`
- `_source_mp3/sfx` → `Sounds for the microSD card/sfx`

Он:

- ищет все `.mp3` в рабочей иерархии
- определяет категорию файла по папке
- выбирает профиль обработки (alarm/system/sfx/music)
- перекодирует в нужный формат WAV
- поддерживает стабильные имена вроде `alarm_1__...wav`
- пропускает уже готовые WAV с теми же параметрами, чтобы не перепроцессовывать повторно
- пишет `audio_manifest.csv` с результатами конвертации

### Параметры запуска

Скрипт понимает следующие аргументы:

```
--profile alarm
--profile system
--profile sfx
--profile music
```

Дополнительно можно переопределить параметры:

```
--sample-rate 22050
--channels 1
--bit-depth 16
--codec pcm_s16le
```

Примеры:

```
python ".\Data to load\convert_mp3_to_wav.py" --profile alarm
python ".\Data to load\convert_mp3_to_wav.py" --profile system
python ".\Data to load\convert_mp3_to_wav.py" --profile alarm --sample-rate 22050 --channels 1
```

### Профили по умолчанию

| Профиль | Частота | Каналы | Битность | Кодек |
|---|---:|---:|---:|---|
| alarm | 22050 Hz | 1 | 16-bit | pcm_s16le |
| system | 16000 Hz | 1 | 16-bit | pcm_s16le |
| sfx | 16000 Hz | 1 | 16-bit | pcm_s16le |
| music | 22050 Hz | 2 | 16-bit | pcm_s16le |

### Требования к окружению

Для корректной работы скрипту нужен:

- Python 3.x
- FFmpeg, установленный в PATH, либо находящийся в локальной папке проекта
- стандартные библиотеки Python: argparse, csv, pathlib, re, shutil, subprocess, sys

Если FFmpeg не найден, скрипт выведет понятную ошибку и предложит положить ffmpeg.exe в одну из ожидаемых папок проекта.

## 6. Правила для корректного заполнения микросхемы звуков

Рекомендуемые правила:

1. Все файлы в конечной FAT/SD папке должны быть WAV.
2. Не смешивать MP3 и WAV в одной папке финального назначения.
3. Не оставлять “временные” файлы в корне карты памяти.
4. Имена должны быть стабильными и понятными.
5. Для каждой категории должен быть свой индексной набор.
6. После генерации новых файлов всегда пересматривать manifest и проверить, что категория и частота соответствуют ожиданиям.
7. Если добавляете новые файлы в `_source_mp3`, не переименовывайте старые файлы без необходимости.

## 7. Рекомендуемый рабочий процесс

### Вариант A: “Всё уже готово в WAV”

1. Подготовить папки `alarms/system/sfx`
2. Сгенерировать WAV требуемых параметров
3. Переименовать в правильный формат
4. Загрузить на microSD в корень

### Вариант B: “Есть только MP3 / скачано / из кассеты”

1. Подготовить структуру `_source_mp3`
2. Разложить файлы по категориям
3. Запустить скрипт
4. Проверить `audio_manifest.csv`
5. Скопировать из `alarms/system/sfx` в корень microSD

### Вариант C: “Нужно быстро проверить качество”

1. Сделать отдельную папку с 1–2 тестовыми файлами
2. Запустить скрипт с нужным профилем
3. Послушать результат на устройстве
4. Если качество устраивает — расширять набор файлов

---

## 8. Что нужно помнить

- Для устройства критично, чтобы WAV-файлы были в нужной папке и имели правильный формат.
- Неиспользуемые настройки или “удобные” форматы могут привести к неработающему воспроизведению.
- Скрипт — это консистентный путь: он берёт исходники, нормализует их и создаёт итоговые файлы без ручного хаоса.
- manual load — это “быстрая разовая команда”; script flow — это “системный, повторяемый и защищённый путь”.

---

## 9. Короче: итоговая схема

Если файл уже готов в `.wav`:

```
SD:/alarms/
SD:/system/
SD:/sfx/
```

Если файл ещё в `.mp3`:

```
Data to load/Sounds for the microSD card/_source_mp3/...
↓
python convert_mp3_to_wav.py --profile xxx
↓
Data to load/Sounds for the microSD card/alarms|system|sfx
↓
копируем в корень microSD
```

---

## 10. Полезные рекомендации

- Сохраняйте исходники в `_source_mp3` вместе с папками по категориям. Это делает процесс воспроизводимым и безопасным.
- Для каждого нового набора звуков лучше вести список того, какие файлы уже были загружены, чтобы не терять соответствие между device ID и реальным треком.
- Файл `audio_manifest.csv` — ваш простой журнал, который показывает, что было обработано, что было пропущено, а что не удалось.
- Периодически проверяйте, что в конечных папках нет лишних мусорных WAV-файлов.

Если всё сделано по этому руководству, карточка microSD будет содержать корректные файлы в правильных местах с правильными настройками аудио для устройства Nixie Clock.
